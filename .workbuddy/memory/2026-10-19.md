## intent_route prompt 对齐（同日，v4）

- 原 prompt 与代码 5 处不一致：缺 `bank_code`（死分支）、未提 `edu_course_doc`、content 鼓励抽课程实体（代码会剥）、题型不存在无处置规则、答案分布无字段约束
- prompt 改动：补 `bank_code`/`course_doc`；content 限定最多给题型/题库/题码；题型判定改 4 条有序规则（枚举内原样填 / 泛称省略 / 枚举外省略+ambiguous / 其余一律省略）；答案分布要求 `answer+distribution+判断题`；聚合示例标注字段映射；实体只输出有值字段
- 代码兜底 3 处（`node_intent_route` / `node_aggregate`）：
  1. 题型推断防护：题型词必须出现在问题原文（含「选择题」泛称）才保留 → 防「有什么假设」被推断成「简答题」后错误收窄召回路
  2. 答案分布兜底：「答案 + 分布/占比/正确率」直接置 `answer/distribution`，未指定题型补「判断题」
  3. `aggregate_op` 缺省推断：有 `aggregate_field` 默认 `group_by`（原默认 count 会丢分组、导致答案编造明细）
- **prompt 经验（重要）**：不要在 prompt 里放真实取值当示例（v2 写「如"通用程序设计题库"」→ Q01–Q04 凭空填该题库）；必须显式写「只输出有值字段」（否则 13 个字段全列空值）；业务唯一确定的映射交代码兜底
- 验证：44 条 A/B intent **0 差异**；A3-20 从误留空恢复；A3-26 三轮稳定 145/90；A3-25 恢复 `bank_code`；黄金集指标 **全部持平**（Hit 0.8125 / Recall 0.7969 / MRR 0.724 / question 1.0 / doc 0.875），未命中仍 D06/D15；冒烟 12/12
- 教训：只跑冒烟拦不住实体级错误（A3-20 只断言答案含「14」，实体错也能过），prompt 改动必须 A/B + 全量指标
